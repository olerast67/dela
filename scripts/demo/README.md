# Демо-аккаунт для вызова «прочитай мою задачу»

Два скрипта для ролика про сквозное шифрование:

- `seed.ts` наполняет отдельный демо-аккаунт правдоподобными данными обычного человека за 8 недель и кладёт одну секретную задачу, текст которой вы вводите сами;
- `export.ts` на сервере выгружает всё, что сервер хранит об этом аккаунте, кроме того, что дало бы перебор пароля или раскрыло других людей, проверяет выгрузку и печатает сводку для страницы вызова.

Что публикуется и что сервер видит открыто: [docs/challenge.md](../../docs/challenge.md).

## 1. Приглашение для демо-аккаунта

Регистрация на сервере закрыта, нужен код приглашения. Его выдаёт администратор:

1. Войдите в веб-клиент своим аккаунтом администратора.
2. Настройки → «Приглашения» → «Создать приглашение».
3. Появится ссылка вида `https://dela.olerast.com/?invite=КОД`. Для скрипта нужен только `КОД` (часть после `invite=`). Код действует 7 дней и подходит одной регистрации.

Регистрировать демо-аккаунт в веб-клиенте не нужно: клиент при регистрации добавляет приветственные задачи, а скрипт наполняет только пустой аккаунт. Регистрацию сделает сам скрипт.

## 2. Наполнение (на своём компьютере)

Из корня репозитория, Node.js 22.18 или новее, после `npm ci`:

```
node scripts/demo/seed.ts --server https://dela.olerast.com --email ПОЧТА_ДЕМО --invite КОД --secret-prompt
```

Скрипт спросит:

1. пароль демо-аккаунта (ввод скрыт, без звёздочек);
2. текст секретной задачи и ещё раз его же (ввод скрыт);
3. если войти не удалось, пароль ещё раз: тогда он регистрирует новый аккаунт.

Параметры:

| Параметр | Что делает |
| --- | --- |
| `--server URL` | адрес сервера; без него спросит |
| `--email ПОЧТА` | почта демо-аккаунта; без неё спросит |
| `--invite КОД` | код приглашения; нужен только для регистрации |
| `--secret-prompt` | спросить текст секретной задачи; без него секретной задачи нет |
| `--tz ПОЯС` | пояс для дат, например `Europe/Moscow`; по умолчанию пояс компьютера |
| `--force` | наполнять, даже если в аккаунте уже есть задачи |

Что важно знать:

- Пароль и секрет нигде не печатаются и не пишутся в файлы. В сообщениях об ошибках только код ошибки.
- Ключ восстановления не показывается: для демо он не нужен, а показанный на экране при съёмке он бы открыл аккаунт. Забыли пароль: создайте новый демо-аккаунт.
- Скрипт отказывается наполнять аккаунт, в котором уже есть задачи (защита от запуска на основном аккаунте). Повторный запуск по тому же аккаунту тоже откажет.
- TOTP на демо-аккаунте на время наполнения должен быть выключен.
- Секретная задача лежит в проекте «Личное», без срока и напоминаний: в расписание напоминаний на сервере её текст не попадёт. Длина секрета видна по длине шифротекста с точностью до 64 байт: секрет до 53 байт UTF-8 (около 26 русских букв или 53 латинских) даёт ту же длину, что и большинство записей (168 байт).
- Данные одинаковы при каждом запуске (генератор с фиксированным зерном), даты отсчитываются от сегодняшнего дня: 6 проектов с разделами, около 50 открытых задач с подзадачами, сроками, приоритетами, метками, описаниями в Markdown и двумя комментариями, повторяющиеся задачи, 3 привычки с историей за 6 недель, около 60 выполненных задач за 8 недель, отрезки помодоро, цель дня 4 задачи.
- Время выполнения, создания и отрезков работы в прошлом записано значением полей внутри шифротекста. Метки HLC, которые видит сервер, ставятся по настоящим часам: в выгрузке все операции окажутся в одном коротком интервале в день наполнения. Сервер принял бы и прошлые метки (он проверяет только, что метка не опережает его часы больше чем на 60 секунд), но выдумывать видимое серверу время я не стал.
- Подписку на календарь (.ics) скрипт не создаёт: ей нужен внешний адрес. Если нужна в кадре, добавьте вручную в настройках.
- После наполнения можно войти демо-аккаунтом в приложение для съёмки. Каждое новое устройство и каждая правка тоже попадут в выгрузку (новые устройства, новые метки HLC), поэтому выгрузку лучше делать после съёмки.

## 3. Выгрузка (на сервере, рядом с базой)

Скрипт зависит только от `node:sqlite`, открывает базу только на чтение и ищет аккаунт по почте (`--email`) или id (`--user`). Перед записью он проверяет выгрузку (нет почты и id других пользователей, нет хешей и солей входа, все значения похожи на шифротекст нужной длины, нет посторонних строковых полей); при любой находке файл не пишется и скрипт выходит с кодом 1.

Сервер в Docker (`docker-compose.yml` из репозитория: диск контейнера только для чтения, `/tmp` в памяти). Из папки с `docker-compose.yml` на сервере, файл `export.ts` скопирован рядом:

```
docker compose exec -T dela sh -c 'cat > /tmp/export.ts' < export.ts
docker compose exec -T dela node --disable-warning=ExperimentalWarning /tmp/export.ts --db /data/dela.sqlite --email ПОЧТА_ДЕМО --out - > dela-challenge.json
docker compose exec -T dela rm /tmp/export.ts
```

С `--out -` выгрузка идёт в stdout, сводка в stderr. Без Docker, если на сервере Node.js 22.18 или новее:

```
node --disable-warning=ExperimentalWarning scripts/demo/export.ts --db /путь/к/dela.sqlite --email ПОЧТА_ДЕМО --out dela-challenge.json
```

Сводку «что атакующий видит в открытом виде» (пространства, записи, длины шифротекста, метки времени по дням, устройства) скрипт печатает и кладёт в поле `summary` выгрузки.

## Проверка

```
npx vitest run scripts/demo
```

Тест поднимает сервер в памяти, наполняет демо-аккаунт с тестовым секретом, заводит контрольного пользователя и общие пространства, делает выгрузку и проверяет: нет почты, хешей, секрета и данных контрольного пользователя; ключом демо-аккаунта из выгрузки читается ровно одна секретная задача; статистика, привычки и сад из наполненных данных не пустые; командная строка даёт ту же выгрузку.
