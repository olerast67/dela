# Игровые элементы в Dela (фаза 6)

Задача фазы: сделать так, чтобы закрывать задачи было приятно и чтобы был виден прогресс, не превращая работу в погоню за очками. Основа: теория самодетерминации (Деси и Райан), критика «очков и значков» и подход RECIPE Никольсона, «белые шляпы» Octalysis (развитие, отклик, смысл), модель поведения Фогга, принцип прогресса Амабайл.

## Правила

1. Награда показывает прогресс, а не платит за него. Очков, валюты и уровней нет: внешняя награда вытесняет собственный интерес (эффект гипероправдания).
2. Никаких наказаний. Пропущенный день не сжигает серию сразу, сад не вянет, нет грустных персонажей и фраз «вы потеряете прогресс».
3. Никакого давления страхом упустить: ни уведомлений «не потеряй серию», ни ограниченных по времени наград, ни наград за вход.
4. Никакого сравнения с другими: таблиц лидеров нет. Задачи у всех разные, к тому же это против приватности.
5. Автономия: каждый элемент отключается, есть общий выключатель «Игровые элементы».
6. Всё считается на устройстве из уже синхронизированных данных. Сервер ничего не узнаёт; настройки целей синхронизируются зашифрованными, как остальные.
7. Сложность подстраивается честно: цель дня предлагается по реальному темпу человека, а не «чтобы было больше».

## Пункты

### 6.1 Отклик при выполнении
- Анимация галочки и строки при выполнении, вибрация на телефоне (уже есть), тихий звук по желанию (выключен по умолчанию).
- Закрыта последняя задача дня в «Сегодня»: короткое празднование «День закрыт» и спокойный экран пустого «Сегодня». Так же для пустых «Входящих».
- Изредка вместо обычного тоста тёплая фраза по фактам («Седьмой день подряд с закрытым планом», «Это была самая старая задача во Входящих»). Без случайных наград.
- Учитывать системную настройку «уменьшить движение» (prefers-reduced-motion).

### 6.2 Цель дня и недели, честная серия
- Цель «N задач в день» и «M задач в неделю»; прогресс полоской в «Сегодня» вместо кольца (кольцо остаётся, если цели нет).
- Серия дней с выполненной целью. Выходные дни не считаются (по умолчанию нет, выбираются дни недели). Режим отпуска замораживает серию. Запас: один пропуск в неделю не обрывает серию (как у привычек).
- Подсказка цели по последним двум неделям: «в среднем вы закрываете 6 задач в день».
- Цели и выходные синхронизируются между устройствами.

### 6.3 Итоги недели
- Экран раз в неделю (день и время выбираются, по умолчанию воскресенье вечером), по желанию уведомление.
- Что сделано и в каких проектах; самые давние закрытые задачи; что переносилось три и более раз, с действиями «оставить», «разбить на шаги» (открыть карточку с подзадачами), «удалить»; серии привычек и целей; сколько времени ушло в помодоро.
- Итоги прошлых недель можно открыть из «Статистики».

### 6.4 Вехи
- Тихие отметки в «Статистике»: первые 10/100/1000 задач, месяц с привычкой, неделя без просрочек, «Входящие пусты 7 дней», первая сотня помодоро.
- Новая веха отмечается один раз скромным тостом, без всплывающих окон посреди работы.

### 6.5 Сад
- Визуальная история прогресса: каждый день с выполненными задачами сажает растение; его размер зависит от того, выполнена ли цель дня; привычки и помодоро добавляют листья или цветы.
- Неделя — грядка из семи мест, сад показывает последние недели и месяцы. День без задач оставляет пустую землю; растения не вянут и не умирают.
- Дерево фокуса: во время помодоро растёт росток, законченный отрезок работы превращает его в дерево в саду. Прерванный отрезок оставляет росток, без «засохшего дерева».
- Рисуется на устройстве (SVG или canvas), без внешних картинок; светлая и тёмная тема.

### 6.6 Настройки
- Раздел «Игровые элементы»: общий выключатель и отдельные (звук, празднования, тёплые фразы, итоги недели и их уведомление, сад, вехи). Цели и выходные — там же.

## Устройство

### Настройки (6.6)
- Запись: таблица `game`, запись `settings` в личном пространстве (`packages/core/src/game.ts`). Каждое поле — своя ячейка LWW: правки разных полей с двух устройств сливаются, одного поля — побеждает поздняя. Шифруется вместе с остальными операциями пространства. Нет записи или поле испорчено — значение по умолчанию; старые данные читаются как умолчания.
- Поля (имя в модели → ячейка, умолчание, проверка):
  - `enabled` → `enabled`, true — общий выключатель;
  - `sound` → `sound`, false; `celebrations` → `celebrations`, true; `phrases` → `phrases`, true;
  - `weeklyReview` → `weekly_review`, true; `weeklyReviewDay` → `weekly_review_day`, 7 (1 — понедельник … 7 — воскресенье); `weeklyReviewTime` → `weekly_review_time`, "19:00" (ЧЧ:ММ); `weeklyReviewNotify` → `weekly_review_notify`, false;
  - `milestones` → `milestones`, true; `garden` → `garden`, true;
  - `dailyGoal` → `daily_goal`, null (целое 1..50); `weeklyGoal` → `weekly_goal`, null (целое 1..300);
  - `restDays` → `rest_days`, [] (дни недели 1..7, без повторов, по возрастанию);
  - `vacationFrom` / `vacationTo` → `vacation_from` / `vacation_to`, null (YYYY-MM-DD). Без `vacationTo` отпуска нет; без `vacationFrom` — отпуск до `vacationTo`. Начало позже конца при записи — ошибка, при чтении (поля правили с разных устройств) — отпуска нет.
- Ядро: `doc.getGameSettings()` / `doc.updateGameSettings(patch)` у `Workspace` (и `Doc` личного пространства). Запись пишет только изменённые поля и не попадает в отмену Ctrl+Z; неверное значение — `RangeError`, в данные не попадает. Помощники: `gameFeature(s, 'garden')` — общий выключатель и свой; `isRestDay(s, date)`, `onVacation(s, date)`.
- Веб: `useGame()` из `apps/web/src/hooks.ts` — настройки с перерисовкой при изменении данных (как `useDoc`). Вне компонентов — `doc.getGameSettings()`. Атрибут `data-game` на `<html>` ставит `useGameAttribute()` в `App.tsx`: CSS игровых элементов пишется под `:root[data-game]`, без него приложение выглядит как раньше. Раздел настроек — `GameSettingsSection` в `apps/web/src/ui/Game.tsx`.
- Новый игровой элемент проверяет `gameFeature(useGame(), '…')` и не показывается, когда общий выключатель выключен.

### Отклик при выполнении (6.1)
- Все выполнения идут через `completeWithUndo` (`ui/Task.tsx`) → `completeWithGame` (`apps/web/src/game.ts`).
- Анимация: кружок заполняется от центра (170 мс), пружинит (380 мс) и пускает кольцо; заголовок зачёркивается, строка уходит вправо; задача закрывается через 280 мс, как и раньше. Чип календаря заливает кружок и гаснет за 220 мс. При `prefers-reduced-motion` движения нет, меняются только цвет и прозрачность.
- Звук: два коротких тихих синуса (880 и 1320 Гц, около 0,15 с, громкость 0,05) через WebAudio, в момент нажатия; файлов нет.
- «День закрыт»: если выполненная задача была в «Сегодня» и после неё там пусто, пустое «Сегодня» показывает росток, вспышку листьев (1,5 с, нажатия проходят насквозь) и «Выполнено сегодня: N». На доске — короткая надпись поверх. Пустые «Входящие» — спокойная фраза.
- Тёплые фразы: факты из данных (`completionFacts` в ядре) по приоритету — серия привычки на 3, 5, 7, 10, 14, 21, 30 и каждые 50; первое выполнение дня продолжило серию дней с выполненными задачами (те же отметки); самая старая открытая задача во «Входящих», если висела 7 дней и дольше; просроченных больше не осталось; 5-я, 10-я, 15-я… задача за день; задача ждала 30 дней и дольше. Частота (`pickPhrase`): после фразы следующие четыре выполнения получают обычный тост, фраза возможна с пятого и только если есть факт. Счётчик на устройстве (`localStorage.gamePhraseCount`).

### Цели дня и недели, серия (6.2)
- Ядро: `packages/core/src/goals.ts`. `computeGoals(events, settings, tz, today)` считает по тем же выполнениям, что статистика (`doneEvents`: задачи и экземпляры повторов, без корзины), в том же поясе: `day` (выполнено, цель; в выходной и отпуск `goal: null` и `off: 'rest' | 'vacation'`), `week` (с понедельника: выполнено и цель недели), `streak` (текущая и лучшая серия; `null` без цели дня), `days` (дни текущей недели: число и состояние `done`, `rest`, `vacation`, `allowed`, `missed`, `today`, `planned`). У `Workspace` (все пространства вместе) и `Doc`: `goals(tz, today)`; у `Workspace` ещё `suggestDailyGoal(tz, today)`.
- Серия: день засчитывается, если выполнено не меньше текущей цели дня (истории целей нет). Выходные и отпуск не растят и не обрывают. Первый недобранный день недели (с понедельника, `GOAL_SKIPS_PER_WEEK = 1`) — запас, как у привычек: серию держит, но не прибавляет; второй обрывает. Сегодняшний недобранный день не обрывает. Серия начинается с первого дня с выполнениями.
- Подсказка (`suggestDailyGoal`): среднее выполненных за 14 дней до сегодняшнего, без выходных, отпуска и дней до первого выполнения, округлённое; меньше одной — `null`.
- Веб (`ui/Game.tsx`): `TodayGoal` в заголовке «Сегодня» — полоска «3 из 5» вместо кольца (кольцо остаётся без цели дня), при выполненной цели галочка и акцент, серия подписью от двух дней, в выходной и отпуск подпись вместо цели. `GoalHint` — подсказка в «Сегодня», пока цели нет; закрытие крестиком запоминается в `localStorage.gameGoalHintClosed`. `GoalSuggest` в настройках у поля цели. `GoalStats` — блок «Цели» в «Статистике». Всё скрыто при выключенном общем выключателе.
- «Цель дня выполнена»: `completeWithGame` сравнивает прогресс до и после выполнения; если цель добрана, а день не закрыт, подписчики `onGoalReached` (`GoalBurst`) показывают короткую надпись без конфетти. Закрытый день празднуется только «День закрыт», в пустом «Сегодня» дописано «Цель дня выполнена». Если вместе с этим выпала фраза о серии целей, она идёт в надпись, а тост остаётся обычным.
- Тёплые фразы: факты `goalStreak` (выполнение добрало цель дня, серия от двух дней) и `weekGoal` (добрало цель недели), по приоритету сразу после серии привычки; частота прежняя (`pickPhrase`).

### Итоги недели (6.3)
- Ядро: `packages/core/src/review.ts`. `computeWeekReview(input, tz, monday, today)` — чистый подсчёт по тем же выполнениям и в том же поясе, что статистика; неделя ISO с понедельника. У `Workspace` — `weekReview(tz, monday, today)` (все пространства вместе). Поля: `done`, `activeDays`, `previous` (прошлая неделя, для сравнения фактом), `projects`, `waited` (до 3 закрытых за неделю обычных задач, дольше всего живших от создания, от 1 дня), `postponed` (до 5 открытых задач с тремя и более переносами), `missed` (открытые к концу недели задачи со сроком на этой неделе, без повторов и без уже показанных в `postponed`; у текущей недели до вчера), `work` (минуты и число отрезков помодоро), `habits` (серия на конец недели и выполнения за неделю), `goals` (дни с выполненной целью дня, серия на конец недели, цель недели; `null` без целей). У текущей недели всё считается на сегодня (`current`).
- Переносы срока: истории изменений срока в данных нет (ячейка `due` хранит только последнее значение), поэтому `Doc.write` при локальной правке дописывает в то же действие запись таблицы `postpone` (`task`, `from`, `to`, `at`, id — uuidv7), если срок открытой задачи был и стал позже по дате. Раньше, снятие срока, время в тот же день — не перенос; сдвиг срока повтора при выполнении или пропуске экземпляра — тоже (`advance` пишет с `postpones: false`). Каждый перенос — своя запись, а не LWW-счётчик: переносы с двух устройств офлайн складываются (как отрезки помодоро). Отмена Ctrl+Z удаляет запись вместе с правкой (`postpone` в `DELETABLE`); при удалении навсегда записи помечаются удалёнными. «Оставить» пишет в задачу ячейку `postpone_kept` (время): переносы до неё не считаются (`Doc.postponeKeptAt`, `keepPostponed`). Порог — `POSTPONE_THRESHOLD = 3`.
- Когда: `reviewWeekOf(date, day)` — в пятницу, субботу и воскресенье итоги этой недели, в остальные дни прошлой. `lastReview(settings, now, tz)` — последний наступивший момент (день и время из настроек), `reviewsBetween` — моменты в окне для уведомлений, `reviewWeeks` — последние 12 недель для списка.
- Веб (`apps/web/src/ui/Review.tsx`): маршруты `#/review` (список последних 12 недель с числом выполненных, ссылка «Итоги недель» в «Статистике») и `#/review/<понедельник>` (страница недели, стрелки к соседним неделям). Действия у часто переносимых: «Оставить», «Разбить на шаги» (`requestSubtaskInput` из `TaskPanel.tsx`: карточка открывается с полем новой подзадачи в фокусе), «Удалить» (в корзину, тост с отменой).
- Карточка `ReviewCard` в «Сегодня» (рядом с `GoalHint`): только при `enabled` и `weeklyReview`, с момента итогов двое суток, пока её не закрыли или не открыли эти итоги; последняя увиденная неделя хранится в `localStorage.gameReviewSeen`.
- Уведомление при `weeklyReviewNotify` (и `enabled`, `weeklyReview`): синтетическое напоминание без задачи с ключом `review:<понедельник>` в `alerts()` контроллера, рядом с утренней сводкой. Отсюда оно попадает в расписание Android (`extra.review` → экран итогов), в push-расписание этого устройства (поле `review` в зашифрованном содержимом, service worker открывает `#/review/<неделя>`) и в уведомление Windows и браузера при открытом приложении; тост «Открыть» ведёт на экран итогов.
